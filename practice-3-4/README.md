# Practice 3-4

Проект для демонстрации практик по фронтенд и бэкенд разработке.

Реализовано:

- авторизация и работа с товарами;
- refresh token и сессии;
- PWA: `manifest.json`, `service worker`, App Shell;
- офлайн-доступ к интерфейсу и сохранённому списку товаров;
- WebSocket-обновления товаров в реальном времени;
- уведомления через `Notification API`.

## Структура

- `backend` - Express API на `http://localhost:3000`
- `frontend` - React-приложение на `http://localhost:3001`

## Требования

- `Node.js`
- `npm`

## Установка

Устанавливать зависимости отдельно не нужно, они уже лежат в проекте. Если понадобится переустановка:

```powershell
cd backend
npm install

cd ../frontend
npm install
```

## Запуск

Открыть два терминала.

### 1. Запуск backend

```powershell
cd practice-3-4/backend
node app.js
```

После запуска доступны:

- API: `http://localhost:3000`
- Swagger: `http://localhost:3000/api-docs`
- тестовый админ:
  - `admin@test.com`
  - `admin123`

### 2. Запуск frontend

```powershell
cd practice-3-4/frontend
npm start
```

Приложение откроется на:

- `http://localhost:3001`

## Сборка

Проверочная production-сборка:

```powershell
cd practice-3-4/frontend
npm run build
```

## Что демонстрировать по практикам

## Практика 13. Service Worker

Что показать:

- открыть приложение в браузере;
- открыть DevTools -> `Application` -> `Service Workers`;
- убедиться, что `sw.js` зарегистрирован;
- показать, что после первой загрузки интерфейс продолжает открываться без сети.

Как проверить:

1. Открыть сайт и авторизоваться.
2. Убедиться, что список товаров загрузился.
3. В DevTools включить `Offline`.
4. Обновить страницу.
5. Показать, что App Shell загружается, а товары берутся из локального кэша.

## Практика 14. Web App Manifest

Что показать:

- файл `frontend/public/manifest.json`;
- вкладку DevTools -> `Application` -> `Manifest`;
- иконки, имя приложения, `theme_color`, `display: standalone`.

Как проверить:

1. Открыть приложение в Chrome или Edge.
2. Перейти в `Application` -> `Manifest`.
3. Показать, что манифест читается без ошибок.
4. При желании нажать установку PWA из адресной строки браузера.

## Практика 15. HTTPS и App Shell

Что реализовано в рамках локальной версии:

- App Shell архитектура через `service worker`;
- кэширование оболочки приложения;
- офлайн-открытие интерфейса.

Что сказать на демонстрации:

- для полного HTTPS/Let's Encrypt нужен отдельный деплой на сервер;
- локально показана именно часть `App Shell`, которая относится к PWA;
- при отключении сети приложение всё равно открывается и отображает сохранённые данные.

## Практика 16. WebSocket и Push. Часть 1

Что показать:

- backend поднимает WebSocket-канал на `ws://localhost:3000/ws`;
- frontend автоматически подключается к нему;
- при создании, редактировании или удалении товара изменения прилетают в реальном времени.

Как проверить:

1. Открыть приложение в двух вкладках браузера.
2. В первой вкладке войти под админом.
3. Во второй вкладке тоже открыть приложение.
4. В первой вкладке создать или изменить товар.
5. Показать, что во второй вкладке список обновился без перезагрузки.

## Практика 17. Web Push API и Notification API

Что реализовано:

- кнопка включения уведомлений;
- запрос разрешения через `Notification.requestPermission()`;
- показ уведомления при realtime-событиях.

Как проверить:

1. Открыть приложение.
2. Нажать `Включить уведомления`.
3. Разрешить показ уведомлений в браузере.
4. В другой вкладке создать или изменить товар.
5. Показать системное уведомление о событии.

Важно:

- полноценный Web Push с подписками и отправкой с удалённого сервера здесь не разворачивался;
- в проекте показаны `Notification API` и интеграция уведомлений с realtime-событиями.

## Практика 18. Подготовка к контрольной работе

Что можно показать как итог:

- приложение работает как PWA;
- есть `manifest.json`;
- есть `service worker`;
- работает офлайн-режим;
- есть realtime через WebSocket;
- есть уведомления в браузере;
- есть авторизация, refresh token, сессии и CRUD товаров.

## Сценарий быстрой демонстрации преподавателю

1. Запустить `backend`.
2. Запустить `frontend`.
3. Открыть приложение и войти под `admin@test.com / admin123`.
4. Показать список товаров и работу CRUD.
5. Открыть DevTools -> `Application` -> `Manifest`.
6. Открыть DevTools -> `Service Workers`.
7. Включить `Offline` и обновить страницу.
8. Показать, что интерфейс и сохранённые товары доступны офлайн.
9. Включить уведомления.
10. Открыть вторую вкладку и изменить товар.
11. Показать realtime-обновление и уведомление.

## Полезные замечания

- если service worker не обновился сразу, в DevTools можно нажать `Unregister`, затем обновить страницу;
- если уведомления были запрещены, разрешение можно поменять в настройках сайта в браузере;
- если порт `3000` или `3001` занят, нужно освободить его перед запуском.
